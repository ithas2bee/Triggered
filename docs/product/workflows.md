# Core User Workflows

## Capture an observation

1. The user eats a food.
2. The user records the food and consumption time.
3. The user records a reaction or feeling.
4. Triggered stores the observation.

Capture should remain short and mobile-friendly. Optional context may be added
by a future story without making the basic workflow slow.

## Review history

The user can review previous observations in chronological or otherwise useful
history views. The history represents the user's reports and should preserve
the distinction between recorded facts and later analysis.

## Understand a pattern

The system may aggregate observations for a food and present a trigger level.
The presentation must explain that the level reflects the user's reported
pattern. When evidence is insufficient, it must show Insufficient Data rather
than overstate certainty.

## Secondary web experience

The web client is intended for history review, trends, detailed observation
examination, data management, and understanding patterns. It shares the same
backend and core rules as mobile.
